Topic 1: Registration and Password Hashing

Coach: Can you tell me about how you handle user registration in your application? Specifically, how do you handle password hashing when creating new users?

Akumu Maria: In my application, I use bcrypt to hash passwords before storing them in the database. When a user registers, I never store their actual password. Instead, I create a secure hash of it. Here's the code from my registration controller:

async function processUserRegistrationForm(req, res) {
  const { name, email, password } = req.body;

  try {
    // Hash the password before storing it
    const salt = await bcrypt.genSalt(10);
    const passwordHash = await bcrypt.hash(password, salt);

    // Create the user in the database
    const userId = await createUser(name, email, passwordHash);

    req.flash('success', 'Registration successful! Please log in.');
    res.redirect('/login');
  } catch (error) {
    console.error('Error registering user:', error);
    req.flash('error', 'An error occurred during registration. Please try again.');
    res.redirect('/register');
  }
}

I use bcrypt.genSalt(10) to create a random salt, then bcrypt.hash() to combine the password with the salt and create a secure hash. The number 10 is the salt rounds, which means the hashing will be done 10 times to make it harder for attackers to crack.

Coach: That's a great explanation! I can see you're using bcrypt with a salt. Why is it important to use a salt when hashing passwords?

Akumu Maria: The salt is important because it makes each password hash unique, even if two users have the same password. Without a salt, if two users both use "password123", their hashes would be identical, which would make it easier for attackers to use rainbow tables or pre-computed hash databases to crack passwords. By adding a random salt to each password before hashing, even identical passwords will have completely different hashes in the database. This makes password cracking much harder.

Topic 3: Protected Access Middleware

Coach: Let's discuss middleware for protecting routes. Can you show me how you use middleware to protect routes, including requireLogin and requireRole?

Akumu Maria: I have two middleware functions in my usersController. The first one is requireLogin, which checks if a user is logged in before allowing access to a route:

const requireLogin = (req, res, next) => {
  if (!req.session || !req.session.user) {
    req.flash('error', 'You must be logged in to access this page.');
    return res.redirect('/login');
  }
  next();
};

This middleware checks if req.session.user exists. If not, it redirects to the login page with an error message. If the user is logged in, it calls next() to continue to the next middleware or the route handler.

I also have requireRole, which is a middleware factory that checks if the user has a specific role:

const requireRole = (role) => {
  return (req, res, next) => {
    // Check if user is logged in first
    if (!req.session || !req.session.user) {
      req.flash('error', 'You must be logged in to access this page.');
      return res.redirect('/login');
    }

    // Check if user's role matches the required role
    if (req.session.user.role_name !== role) {
      req.flash('error', 'You do not have permission to access this page.');
      return res.redirect('/');
    }

    // User has required role, continue
    next();
  };
};

This function takes a role parameter (like 'admin') and returns a middleware function that checks if the logged-in user has that role. If not, it redirects them away.

Coach: That's a solid middleware implementation! I notice requireRole is a function that returns another function. Why did you implement it this way instead of a simple middleware function?

Akumu Maria: I implemented requireRole as a middleware factory because it needs to accept a parameter - the role that's required for access. If I made it a simple middleware function, I wouldn't be able to specify which role is needed for different routes. By making it a factory function, I can use it like requireRole('admin') for admin-only routes and requireRole('user') for routes that any logged-in user can access. This makes the middleware reusable and flexible for different authorization scenarios.
